1Password integration (experimental)
=====================================

qutebrowser includes an experimental integration with
https://1password.com/[1Password] that supports credential autofill,
autosave on form submit, and passkey authentication (when using the
experimental native backend).

IMPORTANT: This feature is **experimental**. It requires a separate
daemon (`qute-1pass-sidecar`) and is disabled by default. Set
`onepassword.enabled = true` to enable it.

== Architecture

The integration has three layers:

. **`qute-1pass-sidecar`** — a separate Python process that manages
  communication with 1Password and exposes a JSON-RPC 2.0 API over a
  Unix socket (`$XDG_RUNTIME_DIR/qute-1pass.sock` by default).
. **`OnePasswordClient`** — qutebrowser-side code that speaks JSON-RPC
  to the sidecar over a `QLocalSocket`.
. **JS shim** — injected into pages in MainWorld; intercepts form submits
  for autosave and (if the sidecar advertises passkey capabilities)
  patches `navigator.credentials.get/create`.

The sidecar runs as an independent process so that a crash or a
1Password update never brings down the browser.

== Backends

The sidecar supports two backends, selected via `onepassword.backend`:

`op-cli` (default)::
    Delegates to the official https://developer.1password.com/docs/cli/[1Password CLI v2].
    Supports fill, save, and TOTP. **Does not** support passkeys (the
    CLI does not expose signing primitives). Fully compliant with
    1Password's terms of service.

`native` (experimental)::
    Speaks the internal IPC protocol of the 1Password desktop app by
    reverse-engineering the native-messaging channel used by the
    official browser extension. Supports passkeys. Requires
    `onepassword.experimental_bridge = true`.
+
WARNING: The `native` backend reverse-engineers 1Password's internal
protocol and likely violates 1Password's terms of service. It is off
by default and explicitly opt-in. It may break on any 1Password update.

== Setup

=== 1. Install the sidecar

The sidecar is a separate Python package in
`misc/onepassword-sidecar/`. Install it with pip or pipx:

----
pip install -e misc/onepassword-sidecar/
# or
pipx install misc/onepassword-sidecar/
----

See `misc/onepassword-sidecar/README.md` for full install and systemd
unit instructions.

=== 2. Build and install the bridge launcher

The bridge launcher is a small C program that forks
`/opt/1Password/1Password-BrowserSupport` as a child and acts as a
bidirectional stdin/stdout proxy. It must be installed as a
root-owned binary because 1Password-BrowserSupport verifies its
caller's binary ownership via `/proc/<ppid>/exe`.

This step is *required* for the `native` backend. It is optional
for `op-cli`, but recommended so that the native backend is
available without reinstalling later.

----
make -C misc/onepassword-sidecar/launcher
sudo install -Dm755 -o root -g root \
    misc/onepassword-sidecar/launcher/qute-1pass-sidecar \
    /usr/local/bin/qute-1pass-sidecar
echo qute-1pass-sidecar | sudo tee -a /etc/1password/custom_allowed_browsers
----

The last command adds the launcher's basename to 1Password's official
browser whitelist. Without this entry, BrowserSupport rejects the
connection even if the binary is root-owned.

=== 3. Enable the integration

----
:set onepassword.enabled true
----

=== 4. Start the sidecar

----
:onepassword restart-sidecar
----

This spawns `qute-1pass-sidecar` with arguments derived from the
current `onepassword.*` settings. Check the connection with:

----
:onepassword status
----

== Commands

`:onepassword pick`::
    Open a completion popup with vault items matching the current page
    URL. Tab through entries (title + username shown), press Enter to
    fill the selected item. Requires `op` CLI v2 on PATH and authenticated.
    Use this when `:onepassword fill` picks the wrong item from multiple
    matches.

`:onepassword fill`::
    Find credentials for the current page URL in the 1Password vault
    and inject them into the focused login form. If more than one item
    matches, a hint is shown suggesting `:onepassword pick`. Accepts
    `--otp` flag to also copy the TOTP code (prefer
    `:onepassword copy-totp` for dedicated TOTP copy).

`:onepassword fill-field`::
    Fill only the currently focused input element. Uses the field's
    `type`, `autocomplete`, and `name` attributes to decide whether
    to inject the username or the password. Designed for multi-step
    login forms (Google, Microsoft, etc.) where username and password
    appear on separate pages.

`:onepassword copy-username`::
    Copy the username for the best-matching vault item to the clipboard.
    No auto-clear (usernames are not secrets).

`:onepassword copy-password`::
    Copy the password for the best-matching vault item to the clipboard.
    Clipboard is automatically cleared after 30 seconds.

`:onepassword copy-totp`::
    Copy the TOTP one-time code to the clipboard.
    Clipboard is automatically cleared after 30 seconds.

`:onepassword save`::
    Save the credentials on the current page to 1Password. Also
    triggered automatically on form submit when
    `onepassword.autosave_on_submit = true`.

`:onepassword status`::
    Display sidecar connection status, backend name, capability set,
    and vault lock status. Shows `degraded from <backend>: <reason>` if
    the requested backend fell back to `op-cli`.

`:onepassword restart-sidecar`::
    Restart the `qute-1pass-sidecar` daemon. Reads `onepassword.backend`
    and `onepassword.socket_path` from config and spawns the sidecar
    with matching arguments.

== Suggested keybindings

Add to your `~/.config/qutebrowser/config.py`:

----
config.bind(',pf', 'onepassword-fill')
config.bind(',pk', 'onepassword-pick')
config.bind(',pp', 'onepassword-copy-password')
config.bind(',pu', 'onepassword-copy-username')
config.bind(',po', 'onepassword-copy-totp')
config.bind(',ps', 'onepassword-save')
----

The `,p` prefix leaves `,` free as a leader for other custom bindings.

== Settings

The following settings control the integration. See
link:help/settings{outfilesuffix}[the settings documentation] for
the full descriptions.

`onepassword.enabled`::
    Master switch. Default: `false`.

`onepassword.backend`::
    Sidecar backend. `op-cli` (default) or `native` (experimental).

`onepassword.experimental_bridge`::
    Must be set to `true` to use the `native` backend. Serves as an
    explicit acknowledgement of the ToS caveat. Default: `false`.

`onepassword.socket_path`::
    Override the Unix socket path. Empty string (default) uses
    `$XDG_RUNTIME_DIR/qute-1pass.sock`.

`onepassword.autosave_on_submit`::
    Prompt yes/no when a page submits a form with a password field and
    save the credential if accepted. Default: `true`.

== Passkey support

Passkey support is capability-gated: the sidecar advertises the
`passkey_get` and/or `passkey_create` capabilities in its `ping`
response only when the active backend can actually perform them.

With the default `op-cli` backend, neither capability is advertised and
passkey requests fall through to the built-in Qt WebAuthn dialog
(handled by the standard browser UI — no 1Password involvement).

With the experimental `native` backend, `passkey_get` is supported
when the desktop app is running and accessible. `passkey_create`
depends on whether the 1Password desktop app accepts credential
creation from a non-blessed caller.

IMPORTANT: Sites that test `credential instanceof PublicKeyCredential`
will see the shim's plain-object response fail that check. This is a
known limitation; mitigation via Chrome DevTools Protocol virtual
authenticators is tracked but deferred pending security review.

== Troubleshooting

Sidecar not connecting::
    Run `:onepassword status`. If it reports not connected, check that
    `qute-1pass-sidecar` is running (`ps aux | grep qute-1pass`) and
    that the socket path matches on both sides (`onepassword.socket_path`).

`op` CLI not found::
    Install https://developer.1password.com/docs/cli/[1Password CLI v2]
    and ensure `op` is on `$PATH`. Verify with `op account list`.

Credentials not filling::
    The URL match is domain-based. Make sure the vault item has a URL
    field that matches the current page's hostname. Use
    `:onepassword fill` explicitly if autofill is not triggered.

Passkey prompt not appearing / wrong UI::
    Check `:onepassword status` → `capabilities`. If `passkey_get` is
    absent, the sidecar backend does not support passkeys and the
    standard Qt WebAuthn dialog will be used instead.

Native backend reports "launcher not found"::
    The bridge launcher is not installed at `/usr/local/bin/qute-1pass-sidecar`
    or is not root-owned. Verify with `ls -l /usr/local/bin/qute-1pass-sidecar`
    (expected: `-rwxr-xr-x root root`). Rebuild and reinstall following
    step 2 of the setup instructions above.

Native backend degraded to op-cli::
    `:onepassword status` will show `degraded from native: <reason>`.
    Common causes: launcher not installed or not in
    `/etc/1password/custom_allowed_browsers`, 1Password desktop app not
    running, or vault locked. Fix the stated reason and run
    `:onepassword restart-sidecar`.

Legacy `qute-1pass` userscript::
    The `misc/userscripts/qute-1pass` script uses the deprecated
    1Password CLI v1 API. Use this built-in integration instead.
